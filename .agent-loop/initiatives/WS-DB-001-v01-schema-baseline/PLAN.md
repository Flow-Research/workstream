# Plan

## Approach

1. Provision an isolated PostgreSQL database from the trusted 63-revision head.
2. Add `backend/scripts/schema_baseline_manifest.py`. It emits canonical JSON
   for the `public` schema's tables, columns, defaults, identity/generated
   attributes, primary/foreign/unique/exclusion/check constraints, indexes and
   predicates, sequences (including `last_value` and `is_called`, plus the
   equivalent next identity value), non-system types/enums, routines, triggers, views,
   materialized views, extensions, domains, collations, operator classes,
   row-security policies, and explicit ACL posture. It also
   emits exact ordered rows for the only clean-head seeded tables:
   `authority_control`, `actor_profile_migration_state`, and
   `iso_4217_currency_codes`. Owners, OIDs, database/role names, statistics,
   comments generated by tools, and `alembic_version` are excluded. ACLs use a
   closed canonical principal vocabulary: object owner becomes `owner`,
   `PUBLIC` remains `PUBLIC`, and only explicitly allowlisted application
   grantees may appear by stable logical name. An unknown grantee fails
   extraction; environment-specific login, database, and session-role names
   never enter the manifest.
3. Build one root Alembic revision, `0001_v01_baseline`, from reviewed
   deterministic schema and seed resources.
4. Commit deterministic resources under `backend/alembic/baseline/`:
   `v01_schema.sql`, `v01_reference_data.sql`, and
   `v01_source_manifest.json`. The SQL must contain no owner, database,
   credential, session authorization, or environment-specific statement. It
   emits grants against the allowlisted target-role mapping and applies
   deterministic `setval`/identity restart state after seeded inserts.
5. Provision a second empty database from only the new baseline.
6. Compare normalized old-head and new-baseline manifests byte-for-byte, then
   run ORM, runtime catalogue, fixed-service, mutation-guard, and API proof.
7. Delete the 63 old revisions and replace historical-transition tests with
   current-state baseline and enforcement tests.
8. Delete `backend/migration_contracts/**`, the revision-0023-only service
   identity mapping application module/CLI, and their tests. No runtime module
   may import a historical migration contract after the reset.
9. Update current scripts/docs and semantic-lane ownership. Historical review
   evidence remains untouched unless a current scanner incorrectly treats it as
   executable guidance.
10. Run internal database/security/architecture/test/CI/docs reviews and the
   complete hosted backend coverage gate.

## Rejected alternatives

- Keeping 63 migrations and only adding more CI lanes: improves symptoms but
  retains obsolete compatibility cost.
- `Base.metadata.create_all()`: omits material PostgreSQL enforcement and seed
  state.
- Blind `pg_dump` committed as-is: includes unstable/environment-owned details
  and is difficult to review safely.
- Supporting old development databases with a stamp or bridge: contradicts the
  explicit clean-cut decision and creates an untested second schema path.

## Boundaries

This initiative owns migration representation and current migration tests. It
must not change product models or runtime behavior to make parity easier. Any
manifest mismatch is a baseline defect unless separately approved as a schema
change.

## Verification strategy

- Alembic reports exactly one head/root revision.
- Empty database upgrade succeeds twice on independent databases.
- Normalized old-head and new-baseline object/reference manifests match.
- Sequence runtime/identity restart state matches, and the first generated key
  after baseline installation cannot collide with a seeded row.
- For every canonical ACL entry, effective privileges queried under each
  mapped target principal match between old-head and new-baseline databases;
  unknown or environment-specific principals fail closed.
- ORM-to-database table/column/constraint parity passes.
- Exact authorization/service catalogue parity passes.
- Trigger/function/immutable-guard behavior tests pass.
- Baseline `upgrade()` refuses a non-empty public schema before creating any
  product object. Old revision stamps remain unknown to the new graph and are
  rejected with recreate guidance by a direct `alembic_version` preflight in
  `backend/alembic/env.py` before `context.run_migrations()`, revision-path
  calculation, or product DDL. Tests prove the rejected database's schema and
  rows are unchanged.
- Baseline `downgrade()` raises before mutation and leaves schema/data intact.
- `MIGRATION_TEST_CUSTODY.md` maps every deleted migration test to a current
  invariant test or identifies it as obsolete intermediate-state-only proof.
- All backend semantic lanes and final coverage/API aggregation pass in GitHub.
