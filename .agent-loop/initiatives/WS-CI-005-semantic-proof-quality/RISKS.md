# Risks: WS-CI-005 Semantic Proof Quality

| Risk | Severity | Mitigation |
|---|---:|---|
| A named test cannot observe its claimed invariant | Critical | Proof strength plus test-of-the-test requirement |
| Mock evidence is accepted for transaction or database truth | Critical | Closed custody compatibility and blind fixtures |
| Tenant isolation is tested as missing data | Critical | Require a real foreign resource for repository/isolation claims |
| SQL NULL or composite ownership bypass is missed | Critical | Shared database-integrity failure patterns and direct-SQL proof |
| Schema/runtime/database rules drift | High | Canonical-rule reuse review across all representations |
| Reviewer instructions grow and diverge | High | One shared reference and deterministic adoption validation |
| New rules force infrastructure for small changes | High | Proof type follows claim; risk routing remains proportionate |
| Blind fixtures leak expected findings | High | Raw cases and separate expectations remain isolated |
| Untrusted review text overrides protocol or causes execution | Critical | Prompt-injection fixtures and explicit non-execution proof |
| More ceremony without better detection | High | Forward evaluations must detect real escaped defects |
| Review evidence becomes merge authority | Critical | Receipts remain advisory; human/GitHub authority unchanged |
