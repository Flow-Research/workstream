# WS-CLI-001-16 — Deliberate evaluation-policy correction

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: Managers request a unified setup successor for an exact inspected evaluation policy through its existing public REST operation.

## Intent

Add `workstream project guide correct-post PROJECT_ID GUIDE_ID COMPILATION_ID
POLICY_ID --input FILE --idempotency-key UUID`. The closed public input contains
the complete displayed `target` and manager `reason`; send its original bytes
once to the exact policy's `/corrections` route. Backend owners normalize
feedback, authorize both operations, supersede the policy and allocate one
unified successor atomically. The CLI neither edits policy bodies nor dispatches
that successor, fetches latest, approves or activates anything.

Reuse the existing bounded file reader, caller-key/no-replay transport, post
target decoder/comparison and correction receipt validator. Rename the existing
approval receipt type to the public `PostPolicyReceipt` rather than duplicate
its shape. Require HTTP 201, kind `correction`, RFC UUIDv7 operation and
non-null validated correction, bound to the exact submitted proposal digest.
Require the successor generation to equal the submitted generation plus one
using arbitrary-range arithmetic, not machine-sized integers.
Reject credential-reflecting operation/successor identities. Backend feedback
normalization/hash computation remains backend-owned; structural validation is
not local certification of that business digest. Exact manual replay rechecks
current authority and retained target custody and recovers the immutable receipt.
Unknown writes leave stdout empty and advise unchanged-input/key manual replay.

## Bounded change

Allowed: new `cli/internal/{api,command}/guide_post_correction.go`; receipt type
rename in `cli/internal/api/guide_post_approval.go`; registration in
`cli/internal/command/guide_create.go`; new
`cli/tests/integration/test_guide_post_correction_{http,public_api}.py`; README,
CLI README, affected roadmap, this record, initiative overview and index.

Prohibited: backend/schema/migrations/workflows/dependencies, hidden routes,
existing test weakening, dispatch/activation commands, automatic reads/retries,
local authority/compiler/digest decisions, retained-data deletion, unit-test
suites, skips or coverage/count quotas.

## Risk and review routing

L1 bounded authenticated policy write. Plan review before implementation;
focused architecture/docs/reuse, security and QA/test-delta assignments.
Human focus: exact target/feedback, saved successor versus dispatched work,
fresh replay authority and unconfirmed outcome recovery. No separate planning PR.

The diff exceeds the preferred 500-line L1 guideline because hostile built-process
proof and the actual socket/worker/PostgreSQL journey are separate cohesive
modules. Production changes remain one CLI write and a receipt type rename;
there are no backend, dependency or workflow changes.

## Acceptance criteria

- `test_post_correction_wire_and_invalid_input`: one built-process POST, exact
  bearer/key/original JSON, compact UUID identity and escaped text; malformed,
  duplicate/unknown/null fields, wrong selectors and invalid key send nothing.
- `test_post_correction_receipt_binding`: valid control then wrong policy hash,
  proposal digest, kind, missing/null correction, malformed successor/operation
  IDs, positive but wrong generation/hash/status and unknown fields produce no success. A scratch
  binary with target equality removed must fail the otherwise-valid policy-hash
  substitution at the intended assertion, not fixture setup.
- `test_post_correction_transport_and_credentials`: canonical 4xx versus
  ambiguous denial, unexpected status, drop, redirect, size/content-type errors;
  HTTP/2 GOAWAY sends at most one body; reflected UUID/bearer metadata is hidden.
- `test_post_correction_public_socket_replay_and_authority`: canonical retained
  source fixture, real Flow verifier/uvicorn/PREP/PostgreSQL and explicit actual
  Celery derivation (not queued delivery/live inference). CLI correction agrees
  with persisted public receipt and unified successor; exact replay adds no
  operation/audit/successor. Changed reason (distinct after backend NFC/strip)
  or key, stale target, stored foreign
  project, outsider, invalid/missing token, suspension/reactivation and revoked
  manager grant prove rejection without added state. No activation or dispatch.
- Build/vet/module verify/tidy-diff, Ruff/format, links/stale wording/Commitrail,
  focused isolated integration and role/database cleanup. Retain all full hosted
  Backend/CLI checks unchanged. Existing approval/read proof protects type reuse.
