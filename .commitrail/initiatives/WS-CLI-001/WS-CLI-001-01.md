# WS-CLI-001-01 — Caller-owned Go CLI foundation

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: An independently buildable Go CLI reads the caller's
  canonical profile and exact-project authorization context through the public
  API, with safe credential transport and scriptable output.

## Intent

Give a human or agent-driven terminal one real, trustworthy entry point into
Workstream without copying authentication or authorization into the client.

## Current behavior

`backend/app/api/routes/auth.py` owns both public GET routes. The actor schemas
in `backend/app/modules/actors/schemas.py` and API error envelope in
`backend/app/core/api_controls.py` define their responses. The existing
`mcp_server/` independently maps the same operations; no CLI package exists.
The [external-client drill](../../../docs/engineering/external-api-drill.md)
records successful/denied use of these two selected operations.

## Design and decisions

Cobra exposes `workstream whoami` and `workstream project access PROJECT_ID`,
plus help/version/completion. `WORKSTREAM_API_URL` supplies the trusted API
origin and `WORKSTREAM_TOKEN` supplies one caller bearer per invocation;
neither is persisted. No token-valued command flag is offered. Require HTTPS
except loopback HTTP, reject URL credentials/path/query/fragment, disable
redirects and ambient proxy forwarding, and bound request time and response
bytes. Forward the bearer unchanged; Workstream verifies it and decides whether
the caller may see the exact selected project.

Human output is readable but does not invent authority. `--output json` emits
the exact successful API object to stdout. Errors go to stderr with bounded
status/code/correlation information and nonzero exit status; credentials and
raw transport internals never appear. No retries are needed for these GETs;
future mutations must separately address uncertain execution.

The first GET may perform server-owned admission/touch/audit effects. A CLI GET
is not a promise of a database-read-only operation. Bubble Tea is deferred
because a profile-only full-screen UI adds no useful work navigation.

### Verification design

Test the executable as a user or agent would invoke it, not its individual Go
functions. Keep two process-level suites with non-overlapping jobs:

1. **Real API end to end:** build the CLI, start the current FastAPI app against
   an isolated migrated PostgreSQL database, issue local Flow-compatible test
   tokens, and compare CLI JSON to direct calls to the two public routes. Prove
   first actor admission, profile field parity accounting for server-owned
   touch timestamps, exact-project authorized context and foreign-project
   concealment. The documented local access-administrator bootstrap may arrange
   project authority in the test; the shipped CLI never calls that helper or a
   private endpoint.
2. **Adversarial HTTP integration:** invoke the same built CLI against a
   controlled local HTTP server. Assert exact method/path/query/bearer,
   noninteractive text/JSON/error behavior, and that unsafe origin, redirect,
   ambient proxy, malformed/oversize response, timeout and project-response
   substitution do not leak credentials or report success. This fixture proves
   client boundaries that the real API should not be made to misbehave to test.

Go vet/build and dependency checks are static/package integrity checks, not a
third behavioral test layer. No function-level/unit-test suite, coverage quota,
test-count target or duplicate happy-path matrix is part of this change. A
new test case needs a distinct externally observable contract or reproduced
defect. CI must run both suites; neither may be silently skipped. The CLI's
production call graph is limited to the two currently public REST operations.

## Acceptance criteria

- [x] Independent `cli/` package builds and runs without backend/MCP imports.

  workflows; no unit-test or percentage-coverage gate is added.

## Review findings

Current review freshness belongs to the PR. Material repaired findings, if any,
are retained here rather than duplicating transient check or approval state.

- Reject duplicate JSON members and case-altered unknown fields before emitting
  authority data; raw successful output must not have competing interpretations.
  Accept omitted profile fields with schema-defined defaults without inventing
  fields in JSON output; explicit null arrays remain invalid.
- Tie real authorization-context proof to the already admitted caller, not
  merely parity between two reads. Exercise default project text, sanitized
  errors/correlation IDs and an otherwise valid oversized response.
- The standalone check was not required by existing branch protection. Invoke
  the reusable CLI workflow from Backend and require its success in `test`,
  without changing repository permissions or weakening backend checks.
- Rebuild the frozen candidate before final process verification, with its
  commit embedded in `--version` and clean VCS build metadata.
- `CLI-EXT-001`: Suppress credential-matching server error codes and correlation headers;
  allowlisted characters alone do not prevent credential reflection. Process
  regressions cover both metadata paths in text/JSON output and a safe fallback.
- `CLI-EXT-002`: Compare selected and returned project UUID identities, not textual spellings,
  while retaining the supplied query value. Exercise alternate spellings through
  the HTTP boundary and a compact UUID through the real public API.
- `CLI-EXT-003`: Validate response actor/project UUIDs and every string-array member before
  reporting success. Reject null elements explicitly; Go string zero values must
  not turn malformed authority facts into successful raw JSON output.
