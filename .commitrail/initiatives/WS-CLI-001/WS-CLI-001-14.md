# WS-CLI-001-14 — Inspect exact post-submission policies

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: Managers can inspect an explicitly selected derived evaluation policy, its upstream proposal and saved correction through the existing public GET.

## Intent

Intake approval is now callable through CLI13, but managers cannot inspect the
separately derived evaluation policy in the CLI. Add `workstream project guide
post-policy PROJECT_ID GUIDE_ID COMPILATION_ID POLICY_ID`. Make exactly one GET
to the public exact-compilation `/post-submission-policies/{policy_id}` route.
The caller obtains the policy ID from the existing proposal read once the
backend has derived it; do not fetch latest, poll or execute derivation.

Return the complete public package in JSON and safely escaped text: target,
canonical policy, unified proposal/findings, activation context, lifecycle,
currentness, approval identity and nullable correction. Reading a compiled,
approved or superseded policy can succeed; it never means approval, activation,
checking or current authority for a later request. A saved correction is
displayed, not dispatched. Preserve historical false/current and nullable
selections rather than inventing readiness rules.

Reuse the existing proposal decoder/target/result validators, intake receipt
validator, UUID identity comparison, arbitrary-range generation representation,
8 MiB proposal response envelope, common deadline, bearer transport and renderer.
Extract the existing proposal decoding block as one shared helper, preserving
its current behavior. New typed values represent only this public wire shape.
Validate closed required/null/array members and resource identity bindings;
do not implement catalogue membership, compile policy, recalculate business
hashes or decide permissions locally. Keep API-selected lifecycle facts intact.

Alternative rejected: automatically derive, approve and activate after a read
would silently make manager decisions and create another lifecycle owner.
No new dependency, abstraction framework or backend capability is needed.

The diff exceeds the preferred 500-line L1 guideline because it includes the
complete typed public package plus built-process and real socket/worker/SQL
proof. It remains one cohesive read operation: no second business boundary,
backend implementation, dependency, workflow or existing-test rewrite is added.

Allowed: new `cli/internal/api/guide_post_policy.go` and
`cli/internal/command/guide_post_policy.go`; registration in

`cli/tests/integration/test_guide_post_policy_http.py` and
`cli/tests/integration/test_guide_post_policy_public_api.py`; CLI/root README,

Prohibited: backend/MCP/workflow/dependency/schema/migration edits, private or
hidden routes, new authorization or compilation logic, approval/correction/
activation commands, polling/automatic pagination/retry, data cleanup,
unit-test suite, skips or percentage quotas. Existing tests retain their proof.

## Acceptance criteria

- Built-process HTTP: one exact GET and bearer, four explicit selectors,
  compact UUID identity normalization, full JSON/text parity and safe terminal
  rendering. Reject local invalid selectors without a request.
- Closed package validation: nested proposal and upstream receipt reuse,
  compiled policy entries and activation selectors, positive arbitrary-range
  generations, all nullable pairs and correction receipt; refuse missing,
  duplicate, null-required, unknown-field, malformed and substituted resources.
  Denials/redirects/oversized or broken responses leave stdout empty and nonzero.
  No local catalogue evaluation or hash recomputation is claimed.
- `test_post_policy_public_socket_history_and_fresh_authority`: canonical
  `source_case` arranges retained source/compilation/finalization; actual public
  socket and Flow/PREP/PostgreSQL perform intake approval. Explicitly invoke
  the real Celery derivation task in an isolated subprocess using its canonical
  identity, with a non-eager memory broker. This proves executed worker/SQL
  derivation, not queued broker delivery, live inference or deployment.
  Discover the policy through public proposal read, then compare CLI with REST
  and persisted canonical body/hash. Confirm no CLI approval or activation.
  Test compiled and REST-approved observations; create a REST correction and
  inspect the retained superseded/non-current package and exact successor.
  Store a foreign project; deny substituted selectors, outsider, missing/bad
  token, suspended actor and revoked grant after positive controls. Reads must
  not add policy operations or activate the guide. No HTTP auth override.
- Falsification: scratch build removes only selected-policy identity binding;
  the named valid-UUID substitution process case must fail at its rejection
  assertion, not fixture setup.
- Build/vet/module verify/tidy-diff; Ruff/format; complete CLI integration via
  the isolated runner, with cleanup metadata; links, stale wording and Commitrail.
  Full backend completeness and real integration remain required hosted CI.

## Risk and review routing

L1 scoped authenticated policy/evidence disclosure; no invented urgency.
Plan review first traces real worker fixture feasibility and historical package
semantics. Implementation uses three bounded assignments: architecture/docs/
reuse, security, and QA/test-delta, selected by actual impact. Lead runs shared
checks once and freezes a clean head; reviewers do not rerun the full suite.
Human focus: exact resource membership, complete historical disclosure without
claiming readiness, and read-only boundaries. No new human design decision is
required by this existing public contract.
