# WS-CLI-001-15 — Deliberate post-submission policy approval

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: A manager can separately approve the exact displayed evaluation policy through the existing public REST operation.

## Intent And Design

CLI14 exposes the canonical evaluation policy and exact target. The missing
next step is `workstream project guide approve-post PROJECT_ID GUIDE_ID
COMPILATION_ID POLICY_ID --input FILE --idempotency-key UUID`.
Send exactly one POST to the public exact-policy `/approval` route. The input
is the public closed object `{"target": <displayed target>}`; transmit its bytes
unchanged. Never fetch latest, select warnings, compile a policy or activate
a guide. Workstream owns fresh authority, currentness, immutable receipts and
manual replay. A successful receipt proves this decision, not activation.

Reuse `readGuideInput`, the caller-key/no-transport-replay HTTP path, UUID
identity comparison, terminal rendering and proposal/upstream validators.
Extract the existing post-target structural validation from its read-specific
package comparison, preserving the read's stronger source binding. Compare
every returned target fact with the submitted target by UUID identity where
appropriate, retaining arbitrary-range generation and exact hash/string facts.
Do not recompute business digests or copy backend authorization/compiler rules.
The response must be a closed `PostPolicyReceipt`, RFC UUIDv7 operation identity,
`kind=approve`, matching target and absent correction. Malformed or uncertain
write responses leave stdout empty and require deliberate unchanged-input/key
replay; a canonical backend 4xx remains a known denial.

Rejected alternative: combining read/approval/activation would silently make
decisions and substitute stale targets. No new dependency or abstraction system
is needed. No material human design decision remains for this existing route.

## Scope

Allowed: new `cli/internal/api/guide_post_approval.go` and
`cli/internal/command/guide_post_approval.go`; shared target-validator extraction
in `cli/internal/api/guide_post_policy.go`; registration in
`cli/internal/command/guide_create.go`; new
`cli/tests/integration/test_guide_post_approval_http.py` and
`cli/tests/integration/test_guide_post_approval_public_api.py`; README,
CLI README, affected roadmap, this record, initiative overview and index.

Prohibited: backend, schema, migrations, workflows, dependencies, private routes,
existing-test edits, correction/activation commands, automatic reads/retries,
local authority or policy decisions, retained-data deletion, unit-test suites,
test skips or coverage/count quotas.

## Acceptance And Proof

- `test_post_approval_exact_wire_and_uuid_identity`: built CLI sends one exact
  bearer/key/JSON POST, preserves supplied path selectors/input bytes, accepts
  canonical/compact spellings of identical UUIDs and arbitrary-range generation,
  and renders only a validated receipt in JSON or escaped text.
- `test_post_approval_invalid_input_is_local`: malformed/duplicate/unknown/null
  fields, upstream mismatch, foreign path selectors and invalid keys cause no
  request. Input is bounded to the existing 1MiB file limit.
- `test_post_approval_malformed_or_substituted_receipt_is_unknown`: wrong kind,
  UUIDv7 variant, correction, nested target changes and malformed shapes fail
  without success output. A named otherwise-valid policy-hash substitution is
  also run against a scratch binary with only that equality check removed;
  it must fail at the intended rejection assertion.
- `test_post_approval_denial_and_transport_uncertainty`: canonical 4xx versus
  ambiguous denial/5xx/drop/redirect/oversize and HTTP/2 GOAWAY. One invocation
  sends at most one POST; no token/body leakage or automatic replay.
- `test_post_approval_public_socket_replay_and_fresh_authority`: canonical
  retained `source_case`, real Flow-token verification, uvicorn socket, PREP
  and isolated PostgreSQL. Public intake approval plus explicit actual Celery
  derivation arranges the policy; this is not broker-delivery or live-inference
  proof. CLI approval equals public read receipt and persisted operation; exact
  replay adds no operation/audit. Fresh other keys, stale hashes, a stored foreign
  project, outsider, bad/missing token, suspension/reactivation and grant revocation
  exercise allow/deny and replay. No decision activates a guide or replaces policy
  bytes. Existing CLI14 read tests protect the shared-validator extraction.
- Build, vet, module verification/tidy-diff, Ruff/format, links, stale wording,
  Commitrail and isolated CLI integration with database/role cleanup. Full
  Backend and complete CLI hosted checks remain required, unchanged.

## Risk And Review

L1 bounded authenticated policy decision. No invented urgency. Plan review before
implementation; three focused assignments: architecture/docs/reuse, security,
QA/test delta. The lead runs shared checks once and freezes a clean candidate.
Human focus: exact decision target, no hidden activation, fresh replay authority
and unconfirmed write recovery. One change equals one PR; do not merge or start
the successor automatically.

The diff exceeds the preferred 500-line L1 guideline because complete hostile
wire and real socket/worker/PostgreSQL proof need separate cohesive modules.
Production changes remain one CLI write and a behavior-preserving validator
extraction, with no backend, dependency or workflow change.
