# WS-CLI-001-12 — Inspect an exact guide proposal

- Initiative: `WS-CLI-001`
- Durable disposition: `Complete`
- Intended merge outcome: Read the complete finalized guide proposal through its existing public API, without approving or executing it.

## Intent

Latest setup exposes a finalized compilation selector, but the CLI cannot yet
show its findings, requirement inventory, proposed intake rules and evaluation
bindings. Add `workstream project guide proposal PROJECT_ID GUIDE_ID
COMPILATION_ID`, issuing exactly one public GET to
`/api/v1/projects/{project_id}/guides/{guide_id}/compilations/{compilation_id}/proposal`.
The explicit compilation must never become an implicit latest lookup. Preserve
the complete response in JSON and escape the complete object in text. A blocked
or non-current proposal is a successful observation, not permission to approve.

Reuse the hardened request-with-response-limit operation, closed JSON decoder,
UUID identity comparison and complete-object renderer. Mirror public value
shapes, required/null/default semantics and scalar/array types, including nested
display-only evidence and complete target identities. Validate selected
project/guide/compilation membership. Retain backend integer ranges. Do not
reimplement catalogue matching, policy validation, digest calculation or
authorization. Allow an 8 MiB bounded response for the backend's 4 MiB stored
compilation plus its projected target and display locations; do not raise other
operation limits. No generic schema framework or new transport/dependency.

## Bounded change

Allowed: new `cli/internal/api/guide_proposal.go` and
`cli/internal/command/guide_proposal.go`, guide command registration, new
`cli/tests/integration/test_guide_proposal_http.py` and
`cli/tests/integration/test_guide_proposal_public_api.py`, CLI/root README,
the existing `cli/tests/integration/test_public_self_service.py` bootstrap
journey's canonical clean-database baseline,
affected roadmap claims, this record, initiative overview and index.

Prohibited: backend/MCP/workflow/dependency changes, hidden APIs, proposal
approval/correction/activation, provider execution, follow-up requests,
polling, document retrieval, local permission/readiness rules, TUI, or another
broad database fixture. Reuse canonical finalized-proposal fixture custody and
production AUTH for real public socket/API proof; fixture arrangements are not
claims that the CLI ran the setup provider.

## Acceptance criteria

- One built process makes one GET with unchanged escaped UUID selectors and
  request bearer; supported alternate spellings compare by UUID identity.
  JSON retains the complete target/findings/policies; text escapes controls.
  Ready, warning, blocked and historical projections stay observations.
- Reject null/missing required facts, invalid nested types and array members,
  malformed/substituted identities, duplicate/unknown fields and extra private
  document handles. Preserve nullable policy and approval references and
  backend integers above int64. Responses above 64 KiB work within the new
  operation's bound; oversized replies fail without partial stdout.
- Retain transport proof and exercise canonical concealment, reflected bearer
  metadata and redirects through existing process fixtures.
- Real PostgreSQL and an actual HTTP socket compare direct API and CLI output
  for a retained finalized proposal. Check OpenAPI exposure and production
  scoped-manager authority; outsider/foreign stored resource, revoked grant
  and suspended actor deny after positive controls. Record fixture seeding
  separately from request authentication/authorization execution.
- A targeted out-of-tree identity-guard mutation must make the named valid
  resource-substitution regression fail at its intended assertion.
- Run all CLI integration/process tests with `run_isolated_tests.py`, inspect
  cleanup, Go build/vet/module verify/tidy-diff, Ruff/format, links, stale
  wording, Commitrail, and full required hosted CI. No skips/deletions,
  coverage quota, new unit suite or gate weakening.

## Risk and review routing

L1: bounded authenticated public proposal inspection, untrusted model-produced
display content and exact resource selection. No invented urgency. Plan review
checks schema/default parity, response bound and fixture reachability before
implementation. Then implement the client/command, process proof and one real
API journey, reconcile docs, freeze a clean candidate, run shared checks and
route architecture/documentation/reuse, security and QA/test-delta as three
focused assignments. No ceremonial nine-reviewer fanout.

Human focus: explicit compilation selection and complete display projection;
intake proposals remain distinct from post-submission evaluation bindings.
Reading does not authorize a decision. Post-policy inspection follows its
separate derivation after upstream approval; it is not implemented here.

The diff exceeds the preferred 500-line L1 guideline because it includes the
complete nested public value projection and its built-process/real-API proof.
It remains one read-only user journey, with no new backend boundary, transport,
framework or broad fixture. Splitting individual response members into separate
PRs would leave an incomplete inspection operation.

## Review findings and integration repair

QA001 exposed type-only acceptance of out-of-range intake limit fields. The
client validates the canonical positive ranges and the file/package 10 GiB
ceiling; optional archive integers retain the backend's uncapped range. Named
process regressions cover valid boundaries and zero/negative/over-ceiling
responses. This is wire validation, not catalogue matching or policy evaluation.

The full suite exposed an existing test-order assumption: self-service
bootstrap expected a fresh database without requesting the shared clean
baseline. Prior proposal fixture actors/grants correctly caused bootstrap
denial. That journey now explicitly uses the canonical clean-database fixture;
all existing bootstrap and authority assertions remain. No product bootstrap,
rejection, database guard or selected-test behavior changed.
