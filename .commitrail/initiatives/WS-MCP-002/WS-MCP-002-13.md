# WS-MCP-002-13 - Task operations and imports

- Initiative: `WS-MCP-002`
- Durable disposition: `Complete`
- Intended merge outcome: Expand the independent MCP adapter from 108 to 132
  tools and cover the current public Workstream product API catalogue.

## Intent

Let authorized system readers, project managers, operators and auditors use the
remaining public project, task, import, service-actor and model operations through
fixed MCP tools. The adapter forwards the caller bearer unchanged. Workstream
remains the identity, authorization, lifecycle, idempotency and storage authority.

## Bounded change

### Allowed

- `mcp_server/`: twenty-four current OpenAPI snapshots, one task-operations tool
  module, fixed gateway/schema/registry bindings, focused tests and package docs.
- `.github/workflows/mcp.yml`: exact 132-tool container and drift assertions.
- This record, the initiative overview/index and affected capability status.

### Not allowed

- No backend, CLI, database, authorization or identity behavior changes.
- No generic HTTP tool, private backend import, direct database access, local
  authorization/replay state, generated idempotency key or automatic retry.
- No health tool, service-actor login, hidden task operation or local object store.

## Design and decisions

The change binds twenty-four current public operations: system project listing;
service-actor provisioning; project-manager and operator task queues; task create,
detail, locked-context, audit-evidence, revision repair and operator start override;
task-import source declaration, exact JSON byte upload/read/status and batch
create/screen/release/status; and four project model profile, budget, usage and
recovery operations. Each tool owns one fixed method/path/status tuple captured
from backend OpenAPI at `f0431385573eb53353c5ffc3c6cdb6a93d206b73`.
After reconciliation onto main, the management and operational task-list
snapshots were recaptured at `517fe54c4ed69777c2a455f2fe9f237e4b4ec184`
because those two response models no longer reject additional properties. The
other twenty-two operation fragments remained identical under the locked Linux
FastAPI, Pydantic and Starlette versions.

The earlier plan expected twenty tools and a 128-tool total. Four public model
operations landed after that census. Current OpenAPI therefore has 132 product
operations after excluding both health routes, so this chunk includes those four
instead of knowingly leaving the current catalogue incomplete.

Import source upload accepts bounded Base64, decodes once and forwards the exact
bytes as `application/json`. Import source read returns only bounded Base64,
media type, server-observed byte count and SHA-256. The adapter owns no source
bytes, replay records or import state. The 8 MiB limit matches the backend public
contract without enlarging the ordinary 64 KiB JSON response budget.

Caller-provided UUID idempotency keys are exposed only where the current public
operation requires them. Project model profile and budget bodies must name the
same project as the fixed path. Successful reads and mutations bind every
selector exposed by the response. A substituted read fails as invalid API data;
a substituted mutation result is uncertain execution. The adapter never retries
a mutation automatically.

## Acceptance criteria

- [x] Exactly 132 unique tools and zero resources/prompts.
- [x] Twenty-four selected OpenAPI snapshots are tamper-evident and drift-tested.
- [x] Every fixed method/path/status binding matches its reviewed snapshot.
- [x] Required keys and bodies are typed tool fields, never ambient MCP metadata.
- [x] Import source bytes are bounded, integrity-projected and never logged.
- [x] Project/body and response selectors fail closed before reuse.
- [x] Caller bearer and keys are forwarded unchanged and never generated.
- [x] No local authorization, replay state, database access or private import.
