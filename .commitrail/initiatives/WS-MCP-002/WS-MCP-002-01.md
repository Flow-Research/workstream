## Design and contributor continuation

1. Use Streamable HTTP with request-level caller credentials. The caller sends
   its existing Flow-issued Workstream bearer in the HTTP Authorization header.
   Forward it unchanged to Workstream; no new identity mechanism or audience.
   This is a deliberate custom authentication integration, not the standard
   remote MCP OAuth profile. Clients must support explicit request headers.
2. Register exactly `workstream_profile_get`. Input is a closed empty object;
   no actor ID, token, URL or headers are tool arguments. Dispatch one fixed
   `GET /api/v1/actors/me`, returning the authorized API response.
3. Read credentials anew per protected invocation. Missing/duplicate/malformed
   headers reject without an API call. Invalid signed tokens reach Workstream,
   whose normal verification rejects them. Never perform an extra profile or
   Flow call to authenticate before the actual API call.
4. Static initialization/tool listing may reveal only the fixed public catalogue.
   It grants no identity or permissions and creates no authenticated session.
   No earlier request's bearer or result can serve a later request.
5. Pull the merged handoff, run the linked experiment, then capture the current
   selected OpenAPI operation and custom-validator semantics. The caller-token
   decision is settled; schema reconciliation is implementation work, not a new
   owner approval or a requirement to finish all 27 bindings.
6. Build the independent package from the tested pattern, not by importing the
   backend drill at runtime. Pin and test the official SDK/client protocol.
   Executed baseline: MCP 2.2.0, OpenAI Agents 0.22.2, protocol `2026-07-28` (with `2025-11-25` legacy compatibility).
   Do not mandate or claim a newer untested protocol or SDK major.
7. Retain fixed trusted outbound destination, no redirects/environment proxies,
   bounded body/response sizes, total and per-operation timeouts, concurrency
   limits, cancellation and no automatic retries. Public deployment uses HTTPS
   and private/trusted backend connectivity. Preserve Origin/Host protections,
   ingress rate limits and authenticated `Cache-Control: no-store`.
8. Keep credentials and sensitive business content out of diagnostics. Return
   declared authorized profile fields without blanket input-echo filtering.
   Production errors preserve safe API status/code/correlation, not raw exceptions.
9. Verify package/container independence, current lifecycle parity and schema
   drift. Submit the one-tool PR with evidence; do not add later tools or merge.

Workstream may use its configured JWKS/introspection policy; no zero-network
production verification claim follows from the local HMAC fixture. An AI client
using a human token acts as that human, not a newly delegated agent identity.

### Foundation Test Proofs

The independent foundation tests (`mcp_server/tests/`) provide concrete evidence for the acceptance criteria:
- **Negative-token / Invalid Credentials**: `test_auth.py` and `test_protocol.py` prove that missing, malformed, or duplicate `Authorization` headers result in an immediate 401 without dispatching an API call (`test_duplicate_authorization_does_not_dispatch`). The actual verification of token signature, issuer, audience, and expiry is correctly delegated to the upstream Workstream service and is proven by the backend authentication tests (e.g., `backend/tests/authentication/test_token_contract.py`).
- **Concurrent-caller Isolation**: `test_protocol.py::test_every_response_is_no_store_and_profile_is_not_cross_caller_cached` sends concurrent requests from different callers (alice and bob) and verifies that each receives their own distinct profile without crossover, and that responses are correctly marked `Cache-Control: no-store` to prevent proxy leakage.
- **MCP Tool Call Cancellation**: `test_protocol.py::test_cancellation_reaches_running_tool_call` proves that a client HTTP disconnect (`http.disconnect` in stateless mode) immediately intercepts the running ASGI task and propagates `asyncio.CancelledError` to abort the upstream Workstream API call. Migrating to MCP SDK 2.x resolved a native termination bug, and our multiplexed ASGI watchdog was refined to enforce `max_request_bytes` without unbounded memory consumption or race conditions.
